# ContextIQ usability validation

Status: ready to run; no real trader results have been collected or claimed.

Recruit 3–5 traders or freelancers. Use one fresh fictional demo workspace per
participant, with permission to observe. Do not ask for bank details or real
customer records. Let the participant work without coaching first.

| Task | Success condition |
|---|---|
| Create a ₹1,250 invoice | Correct client, draft and amount, found without help |
| Record a ₹500 partial receipt | ₹750 outstanding; understands this records money received |
| Ask whether rent and EMI fit if a client pays late | Finds verdict, date window, assumptions and evidence |
| Run the printer price-drop demonstration | Identifies simulated price, ₹2,100 reduction and updated ₹9,900 target; understands cash did not move |
| Review a payment and decline it | Finds recipient/total and knows the agent cannot approve it |
| Disable record sharing | Finds AI & Privacy and understands selected records otherwise reach Groq |

For each task record participant alias, completion without help (yes/no), seconds,
wrong turns, assistance needed, and a short verbatim comment with permission.
Afterwards ask: “What would you check before trusting this answer?” and ask for
clarity/confidence ratings from 1–5. Record failures as well as successes.

Report task completion rate and median time, with participant count and the full
task list. Do not call developer tests user research or invent endorsements.
This small formative study identifies usability problems; it is not population
level proof of adoption or financial safety.
